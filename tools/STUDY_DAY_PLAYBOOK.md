# Study-day playbook

How one day of the statistics track becomes a finished set of artefacts. Day 1 (distribution
shape, 2026-07-28) is the worked reference — every path below has a real Day 1 file behind it,
so when in doubt, open that file and copy its structure.

**To run this:** say *"do the Day 1 treatment for &lt;topic&gt;"* and hand over whatever exists —
notes, a photo of handwritten pages, a chart script, or just the topic name.

---

## What the user supplies

| Needed | Why |
|---|---|
| **The concept** | e.g. "distribution shape and skewness" |
| **The CCH bridge, even roughly** | The one part that cannot be generated. A couple of sentences on *"here's what this means for the flood work"* is enough — Day 1 landed because `bridge_note.md` already had the argument in it. Without it, ask. |
| Handwritten notes (optional) | Photographed page, added at the end of the log entry |
| Existing chart script (optional) | Day 1 had `skew_chart.py` |

---

## The six artefacts

### 1. Log entry → `Claude outputs/5.StatsStudyLog.md`

**Append** a new `## Day N — <Topic>` section; this is one running file, not one per day.

Fixed structure, in order:

```
### Concept                 what the material says, at the level it was taught
### What it actually says   the mechanism underneath — why, not just what
### Bridge to CCH           numbered consequences for the project. THE POINT.
### Interactive companion   links to artefacts 2 and 3
### Feynman check           the whole thing in plain language, no notation
### Open thread             what is unresolved / needs a real dataset
### Handwritten notes       the scan, if there is one
```

An entry without a CCH bridge is a note, not a log entry, and stays in `Stat_Study/`.

### 2. Interactive explainer → `Claude outputs/<Topic>_interactive.html`

Self-contained: inline CSS/JS, no CDN, no build step. Copy
`Skewness_and_Tails_interactive.html` and change the panels.

- 4–6 panels, each *one* idea, building to the CCH point in the last one
- Live controls (sliders/buttons); every number on screen recomputes
- CSS custom properties for colour, with a `prefers-color-scheme` dark block
- Deterministic RNG (`mulberry32`) so a reload shows the same picture
- Local copy → `Stat_Study/03_Notes/<Topic>/`

Wire it up: `HTML_MAP` **and** the `titles` dict in `tools/sync_docs.py`.

### 3. Problem set → `Claude outputs/<N>.StatsProblemsDay<N>.md`

Day 1 = `6.StatsProblemsDay1.md`, ~48 problems. Structure:

| Set | Purpose |
|---|---|
| 0 | Pre-questions, answered from memory before anything else |
| A | Foundations — recognition, no calculator |
| B | Mechanics — the arithmetic, scaffolded (first one fully worked) |
| C | The core argument — comparison and inference |
| D | CCH bridge — why it matters for *this* project |
| E | Hard — synthesis and derivation |
| G | Misconception clinic — plausible statements to dismantle |
| H | Feynman prompts — **no solutions**, the output is the explanation |
| I | Interleaved — unlabelled, done cold a day later |

Also: a "how to use this set" method table at the top, a confidence-rating protocol,
🔭 **[FUTURE]** tags gathered into a forward-map table, and a spaced-repetition schedule.

**Solutions use `<details markdown="1">`, never Material's `???` admonitions.** The `<details>`
form renders on the site *and* on GitHub *and* in VS Code, so the published copy and the
`Stat_Study/02_Practice_Problems/` copy stay byte-identical.

Local copy → `Stat_Study/02_Practice_Problems/`, with a sibling `images/` folder so
`images/<name>.png` resolves in both places.

### 4. Figures → `tools/assets/images/day<N>-*.png`

Generated by `Stat_Study/02_Practice_Problems/day<N>_figures.py` — copy `day1_figures.py`,
which already carries the house style.

- Palette: blue `#2a78d6` = the wrong/assumed model, orange `#eb6834` = reality. More series →
  aqua `#1baf7a`, yellow `#eda100`, magenta `#e87ba4`, in that order, direct-labelled.
- **Light background `#fcfcfb`, not transparent.** No single ink colour is legible against both
  the light and dark site themes; the CSS already rounds and frames images in dark mode.
- One figure per point that a picture makes immediate — not per section.
- Copy to `tools/assets/images/` for the site; keep the originals beside the script.

### 5. Anki → `Statistics::<Topic>`

Under the existing `Statistics` tree, **not** `CCH::` (that holds the research revision decks).
Basic note type, tagged `CCH`, `stats-foundations`, `day<N>`. ~20–25 cards: the facts and
relationships worth having automatic, not the reasoning.

Also write a `.tsv` copy beside the problem set (Front / Back / Tags, tab-separated) as a
portable backup. If Anki is closed, AnkiConnect is unreachable — write the TSV and say so
rather than silently skipping.

### 6. References — **four, maximum**

A table pinned to specific sections or problems: *"if you got stuck on X, go to Y"*, each
time-boxed. Close with an explicit **"deliberately not listed"** line. The user is easily
side-tracked; naming what *not* to read is the part that does the work.

**Verify every URL with a search before writing it.** Do not reproduce links from memory.

## Publishing

Two edits per new page, then push:

1. `MARKDOWN_MAP` (or `HTML_MAP` + `titles`) in `tools/sync_docs.py`
2. `nav:` in `mkdocs.yml`, under `Statistics Study`

```
E:\1.MINICONDA\python.exe tools\sync_docs.py
E:\1.MINICONDA\python.exe -m mkdocs build --strict
git add . && git commit && git push
```

Images need **no** wiring: anything under `tools/assets/` is copied to `docs/`, so
`images/<name>.png` resolves from any page.

Local preview is at **http://127.0.0.1:8000/CCH_Research/** — the subpath matters, bare
`127.0.0.1:8000` 404s. In `cmd.exe` use `cd /d` to change drive.

---

## Verification — do these, they have all caught real errors

- **Compute every number** with Python; never write one from memory. This caught three wrong
  figures in the Day 1 problem set and two in the revision doc.
- **Check figures for label collisions** programmatically — sweep each control across its range
  and compare text bounding boxes. Three collisions were caught this way that a single
  screenshot missed.
- `mkdocs build --strict` — a broken internal link is a hard error.
- After deploying, `curl` the new page and each new image for a 200.
- Confirm `git status` shows nothing under `data/` or `.claude/` — the repo is public and the
  rainfall workbook is private.

## Finally

Append to `2.ResearchLog.md` and update `1.ProjectStatud.md`. Record corrections explicitly —
the log's value is that it says what was wrong, not only what was made.

**And say plainly if a session was infrastructure rather than methodology.** Several
consecutive study-track sessions can pass without the copula workflow moving. That is worth
flagging in the status file, not smoothing over.
